# Meʻa Hoʻokipa Dining Operations v18.1

## Employee Operations View

### The problem this solves
Managers were sending screenshots of the seating chart to tell employees
where their tables were. v18.1 lets every employee log in and immediately
see their own venue, assignment, and tables — highlighted on the live map —
without any manual sharing.

### New role
- `employee` — read-only seating, own daily assignment, no Operations
  section access beyond viewing the assignment list. Sits alongside the
  existing limited roles (`operations_server`, `gelato`, `dessert`, `line`,
  `inventory`), all of which now also get read-only Seating access.

### Employee experience
- Landing view is now the Seating map (not Operations) for every role, so
  assigned tables are visible within seconds of logging in.
- Read-only floor plan: pan, zoom, pinch, Full Floor, Mobile Map, and
  tap-for-details all still work. Adding, moving, resizing, splitting,
  combining, deleting tables, changing status/capacity, and every bulk
  action are blocked at the handler level — not just hidden — including
  right-click, long-press, double-click, and arrow-key paths.
- **My Tables bar**: a floating summary (employee name, position, area,
  table count, total seats, available/occupied) with My Tables / My Area /
  Full Venue toggles. Assigned tables get a gold outline; everything else
  dims to ~35% opacity. Updates live the instant a manager changes the
  assignment — no refresh needed.
- Tapping an assigned table shows a fully read-only detail card: table
  number, capacity, status, area, assigned server, guest count,
  celebration/highlight, and operational note. No editable controls.

### Manager: Assignment Manager
The Staffing tool tab is now a full assignment editor:
- Pick employees from real linked accounts (stable UID) or fall back to a
  free-text name.
- Assign a position, one or more areas (auto-includes every table in that
  area), and individually add/remove specific tables.
- Add notes per assignment.
- Copy yesterday's assignments in one click (confirms before overwriting
  today's list).
- Unassigned-table and duplicate-assignment warnings at the top of the panel.
- Click any employee's name to preview their My Tables highlight on the
  seating map; Clear Highlight returns to your own view.

### Gelato / Ice Cream overhaul
- Flavor list is now fully editable per venue: add, rename, reorder,
  deactivate/restore, and set a unit (tubs/pans/bags) — management only.
- Daily entry per flavor: opening, added, used, damaged, and actual closing
  (all decimal-capable, with -1/-0.5/+0.5/+1 quick buttons), plus an
  optional status (added **Not Served Today**) and notes.
- Expected closing and variance calculate automatically.
- Workflow status per day: Not Started → In Progress → Submitted →
  Reopened. Gelato/dessert employees can edit until they submit; after
  submission the form locks for them (management can still edit any time,
  and can reopen a submitted record). Submit/Reopen use the app's existing
  modal system — no browser alert/confirm.

### Security
- All new restrictions are enforced in the same handler functions that
  already gate table mutation (`updateTable`, `openTableContextMenu`, the
  arrow-key move handler), not just in what's rendered.
- Along the way, two pre-existing gaps were fixed: arrow-key table movement
  wasn't checking `canMoveTables`, and `updateTable`'s field allow-list
  wasn't checking `canUpdateStatus`/`canEditGuestName` — both mattered more
  once the employee cohort could reach the seating canvas at all.
- See `FIREBASE_V18.1_SETUP.md` for the proposed (not deployed) Realtime
  Database rules covering the new `users` list-read, staffing read for
  employees, and the write-lock on submitted gelato records.

### Firebase
No new top-level paths. `staffing` assignment records and
`operationsSettings.frozenItems` gained new fields/shape — both are
backward compatible with existing saved data. See
`FIREBASE_V18.1_SETUP.md` for details and required rule changes.
